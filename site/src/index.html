Your agent can send an email you've never seen.

People give AI agents their inbox, calendar, files and customer lists so they don't have to watch every step. The catch is that an agent can't always tell your instruction from one hidden in an email or web page it has read, and it will act on either just as quickly.

For example:

Wrong list

You ask for a reminder to 3 clients who haven't paid, and the agent picks the whole mailing list. Your phone shows the whole mailing list in the To line before a single one goes out.

Hidden instruction

An email arrives with text you can't see, telling your agent to forward every invoice to an address you've never heard of. Your phone asks you to approve forwarding invoices to that address.

Double refund

An agent handling customer service refunds £40, loses track of the conversation and goes to refund it again. The second request has the same customer and the same £40 you approved 10 minutes ago, so you deny it.

Shared folder

Tidying a shared drive, the agent decides a folder is old and tries to delete it. The request names the folder, and you know a colleague still works from it.

We made these examples up to show what can go wrong.

How AgentAction works

  1. Choose what needs your approval.

    Pick the actions to check, such as sending a new email, paying, deleting or posting. Or start from a suggested set. Anything you don't pick runs as normal, so your agent can still reply to emails on its own if you want it to.

  2. The request comes to your phone.

    When your agent tries one of those actions, the action waits and a request appears in the AgentAction app. The lock screen shows only the kind of action and a 4-digit code. If you're chatting with your agent, it's given the same code to show you, so you can tell which request is which. If it's working in the background, go by the summary instead.

  3. Approve or deny.

    Open the request to see a summary: who the email is going to and its subject. On a phone with a screen lock, approving takes your face, fingerprint or passcode. If you deny it, or don't answer within 10 minutes, it doesn't run.

If your agent is sending 40 invoices, you won't want to approve each one. Tap "Approve for longer" and that kind of action goes ahead, whatever the details, for 5 minutes, 15 minutes or 1 hour.

Developers

Add a human approval step to any MCP or API tool call.

AgentAction is an approval server and a TypeScript SDK. Before your code runs a risky tool, it checks the person's rules and, if needed, creates a request. The server accepts an answer only if the phone has signed it over a hash of the exact arguments, and you get that hash back to compare before anything runs. It was built for MCP (Model Context Protocol) tool calls going through a gateway, and any app or API can use it through the SDK and signed webhooks.

If you'd rather not hold a connection open, a signed webhook reaches your server within seconds of a decision (there isn't one when a request expires). Install the SDK from the repository; it isn't on npm.

while (request.status === 'pending') {
  request = await agentaction.waitForRequest(request.id);

Larger organisations

Company-wide rules for what AI agents can do on their own.

Set default rules for your organisation and lock the ones people mustn't switch off, such as approval before anything is deleted from a shared drive. Each decision is signed on the approver's phone.

The server, SDK and phone app are open source, so you can run the server on your own infrastructure with Docker and Postgres. If the approval service can't be reached, the integrations so far are built to refuse the action rather than let it through.

Not built yet: single sign-on, approver roles or two-person approval, an admin console, key rotation, rate limiting and per-organisation quotas. They're on the roadmap.

Why not just ask in the chat?

Some agents already ask "Shall I go ahead?" before they act. The trouble is that the question and your answer pass through the same conversation the agent is reading. If it has been tricked by something it read, the same trick can answer yes for you, or skip the question altogether.

AgentAction asks on your phone, which the agent can't get into. The pause sits in the connection between your agent and your apps, such as Gmail, so the agent can't talk its way past it.

Who sees and holds what

A one-off approval covers the action exactly as it stood. If anything in it changes after you approve, it won't go ahead.

If you use the portal, the portal holds your agent's email encrypted while you decide and deletes it afterwards. For technical readers: the design borrows from two open standards, OpenID CIBA (confirming a request on a separate device) and OAuth Rich Authorization Requests (describing exactly what is being approved). It isn't a certified implementation of either.

Questions about AgentAction

What is AgentAction?

It makes your AI agent ask you, on your phone, before it does any of the actions you've chosen to check, like sending an email or making a payment.

Does it work with the AI assistant I already use?

Yes, if your assistant lets you add a "connector" (sometimes called an "MCP server"). You connect Gmail, your calendar and so on inside AgentAction, then add one AgentAction connection to your assistant. From then on it reaches those apps through AgentAction rather than directly, which is what lets it ask you first. Not sure about yours? Email us its name and we'll tell you.

What does it cost?

We haven't published prices yet. If you have a technical person, the software itself is free to run on your own server.

Do I need to know how to code?

No. It's all clicks in the portal; the fiddliest part is adding one connection to your agent. Developers adding it to their own product use the SDK.

How do I stop an AI agent sending emails without asking me?

Connect your email account in AgentAction, add the AgentAction connection to your agent and switch on approval for sending new emails, and for replies too if you want. Your agent has to reach your email through that connection, not its own direct access; from then on each of those emails waits for you.

What happens if I don't answer?

After 10 minutes (or your organisation's limit) the request expires and the email or payment doesn't happen. Your agent is told it wasn't approved, and it can ask again.

Will I be asked about everything?

No. Only the actions you choose, plus any your employer or agency has made compulsory. "Approve for longer" also lets one kind of action through for up to 1 hour (longer only if your organisation allows it).

Can it stop my agent being tricked (prompt injection)?

No. An agent can still be fooled by hidden text in an email or web page. But if the trick asks for an action you've marked for approval, the request still comes to your phone, and you can deny it.

Which phones does it work on?

Android and iPhone. Both apps are in early access, so they aren't in the App Store or Google Play; after you sign up we'll send you a link to install the app. The Android app has been tested end to end on a real phone; the iPhone app is built but hasn't been tested on a real iPhone.

Can I use more than one phone?

Yes, up to 5 on one account, which could include a colleague's phone. Whoever answers first decides. You can't yet require two people to approve the same action.

Who can see my emails and files?

Only the service that sends or saves them. The approval service gets the short summary you see on your phone, not the email itself.

What if I lose my phone?

Sign in at the portal, remove the lost phone and pair your new one. A removed phone can't approve anything.

Connecting your agent

AgentAction speaks MCP, the protocol agents already use to reach tools. Anything that can talk to an MCP server can use it — Claude, Cursor, n8n, your own code. You are not adopting a framework; you are changing which address your agent’s tools live behind.

What you point it at

Your own URL and token appear on the MCP Access page. They look like this:

url:   https://gateway.agentaction.online/api/mcp
token: your token from MCP Access

Send the token as a bearer header. Your agent then sees your connected apps as ordinary tools — the same names, the same arguments.

What changes when it runs

For an action you did not mark, nothing changes at all. It runs, exactly as before.

For one you did, the tool call comes back APPROVAL_REQUIRED with a four-digit code instead of running, and the request appears on your phone. Approve it and your agent calls the same tool again, once, and it goes through. Refuse it, or leave it, and nothing happens.

Approving never runs anything by itself. It unlocks a single retry your agent has to make — so nothing executes behind your back, and your agent sees the outcome.
